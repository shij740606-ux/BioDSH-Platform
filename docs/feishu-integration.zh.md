# 飞书接入与项目协作

## 已实现

单个飞书组织的企业自建应用接入：浏览器授权登录、桌面端一次性领取、外部身份关联、本地令牌刷新和撤销复用；管理员配置项目计算节点和飞书项目群；任务运行、完成、失败、取消与中断状态通知通过数据库队列异步发送。

普通用户不配置飞书密钥。管理员在桌面端生成项目邀请链接并指定负责人、分析员或只读角色；用户把链接粘贴到桌面端后，软件自动识别平台地址，通过飞书登录并加入项目。邀请令牌只放在链接片段和系统安全存储中，不写入平台访问日志或 settings.json。桌面端显示飞书姓名和头像，项目负责人可调整角色或移除成员。尚未自动同步通讯录或群成员。

## 管理员接通步骤

1. 在飞书开放平台建立企业自建应用，配置网页授权登录、安全回调地址，并申请登录用户基本信息、机器人发消息和读取指定群信息等所需权限。应用需发布并对目标用户可用；机器人加入项目群。具体权限以开放平台对应接口页为准。
2. 配置平台环境，示例见 deploy/linux/feishu.env.example。App Secret 只存后台受限环境文件，不提交代码、不填写到桌面端。公开地址必须为 HTTPS 域名，用于生成邀请链接；明确设置允许的 tenant_key，未获准组织拒绝登录。生产回调必须 HTTPS，并与飞书登记的回调严格一致。
3. 备好现有平台数据库，执行 alembic upgrade head，部署平台。首次升级严格节点授权前，为每个项目配置可用节点；没有获授权节点的项目会排队。启用飞书登录时自动强制此检查，普通密码登录用户也按相同项目权限处理。
4. 桌面端连接平台后，登录界面出现飞书登录入口。初始管理员仍通过本地账号登录。管理员在设置中选择当前项目，保存可用服务器和飞书群 ID（oc_…）。保存群绑定时平台检查应用能否访问群。
5. 管理员或项目负责人生成项目邀请链接并发给用户。用户在设置中粘贴邀请链接，点击飞书登录，浏览器授权后自动进入获邀项目。

## 协作与运维

项目群绑定只关联通知渠道，不自动授予成员计算权限。任务通知使用飞书消息卡片，不携带访问令牌、原始数据或服务器凭据，仅含任务名称、编号与状态，用户在桌面端查看受权限保护的日志和结果。未实现 Web 任务详情页面，因此暂不生成无法打开的结果链接。

通知每 5 秒领取一条，最多重试 10 次并指数退避；稳定消息 UUID 用于提供方去重。后台进程异常后发送租约过期可重试；实际消息去重仍依赖飞书接口支持。设置页显示最近通知状态和重试次数。通知功能关闭时不会发送，已有绑定的事件仍会入队。多组织分发、通讯录同步、群内取消/重试、高资源任务审批和飞书文档知识库尚未加入。

授权等待 5 分钟过期，state 和桌面领取票据在数据库中仅保存哈希，授权与领取均只能成功一次；取消等待停止桌面轮询，未领取授权自然过期。用户被停用后不能取得登录凭据。飞书用户访问凭据不持久保存，桌面最终平台令牌进入系统安全存储。

## 验证与边界

测试使用模拟飞书返回，覆盖登录重放、组织限制、停用账号、一次性项目邀请、用户资料、项目节点授权、消息卡片、通知去重以及迁移升级/回退/再升级和模型一致性。模拟测试不能证明真实飞书应用配置已正确接通；上线必须使用真实应用完成浏览器授权、项目权限和机器人发送验收。
