# 多服务器自动调度

## 使用

1. 在计算平台部署当前 platform 版本；每台计算服务器安装同版本 Worker，按 [Worker 部署说明](server-worker.zh.md) 注册、配置 executor 白名单并运行。
2. 桌面端设置平台地址、登录并选择项目。服务器管理卡片的“绑定计算 Worker”关联对应节点。只保存 SSH 信息的服务器不参与调度。
3. 计算任务填写 CPU、内存、GPU 数量和每张 GPU 最小显存。默认自动选择全部节点；限定范围可勾选一台或多台，也可读取 SSH 页面已勾选且绑定的节点。范围作为任务快照保存，后续修改 SSH 勾选不会修改已提交任务。
4. 平台筛掉离线、采样过期、运行环境不匹配、Worker 忙碌和资源不足的节点，优先选择 CPU 使用率较低的合格节点，同负载优先剩余内存、CPU。资源不足继续排队，任务详情显示各节点原因。

## 并发与恢复

领取前在同一数据库事务内写锁计算节点，重新评估全部节点，并条件更新 queued 任务。数据库锁跨平台进程生效；目前使用粗粒度锁，后续吞吐量需要时改为资源池锁。现有 Worker 单任务串行运行，因此每台节点同时仅预留一个活动任务，避免将任务安排给无法并行领取的 Worker。

assigned 租约过期重新排队；已经 preparing/running/cancelling 的租约过期变为 unknown，不自动重新运行，并继续占用节点直到人工确认，避免重复分析。完成、失败或确认取消后，活动任务预留解除；新的心跳 running_jobs=0 后可继续调度。

GPU 按可用显存筛选并保存实际设备编号，Worker 设置 CUDA_VISIBLE_DEVICES。Worker 启动前重新检查资源和分配的 GPU；资源变化时拒绝启动并记录失败，用户可重新提交。CPU 的线程环境变量提供给兼容分析软件，但当前没有 cgroup 内存/CPU 硬限制，不应当作操作系统级隔离。

## 部署边界

本功能复用已有数据库 JSON 字段，无需新增迁移；平台和 Worker 必须一起更新。SSH 绑定不包含自动安装 Worker，也不会静默部署后台进程。没有平台登录、Worker 注册和 executor 配置时，仍可使用 SSH 资源查询，但不能使用平台自动调度。

第一版是一项任务自动选一台服务器，多项任务可分布到不同服务器；没有单任务跨节点拆分、节点内并行 Worker、GPU MIG 或抢占。权限沿用项目角色，节点资源池权限尚未独立细分。

## 验证

新增测试覆盖低负载优先、节点范围、GPU 编号分配、数据库并发领取、完成释放、显存不足排队、unknown 占用保留、越权查询拒绝及 Worker 启动前资源复查。
